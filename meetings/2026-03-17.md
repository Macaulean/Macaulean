## Summary

The meeting focused on discussing polynomial implementations and reordering tactics in Lean. Jay presented work on a branch for polynomial reordering, which aims to reorder expressions based on variable lists while moving constants to the front. Matthew demonstrated Claude's code for polynomial manipulation, including a denote function that evaluates polynomials in a given context. The group discussed various approaches to implementing polynomials, including the use of geobuckets and monomial orders. They also touched on the challenges of proving polynomial equality and the need for efficient kernel-level operations. The conversation ended with a brief discussion about an upcoming ICMS conference and potential speaking opportunities.

## Topics

### Polynomial Reordering Implementation Discussion

Jay discussed his work on a new branch for polynomial reordering, which aims to reorder expressions based on a specified variable order and move constants to the front. He explained the current limitations of the code, which can only reorder products and not sums, and the challenges in efficiently handling large expressions. Michael suggested using a "geo-bucket" data structure from Macaulay 2 to improve efficiency, particularly for handling polynomials with many terms. The group also discussed the implementation of polynomial types in Lean and Mathlib, with Matthew showing Claude's code for a polynomial type that uses Lean's built-in grind com ring functionality. The conversation touched on the differences between polynomial implementations in various systems and the challenges of proving theorems about expressions at the level of abstract indices rather than concrete elements.

### Grind Algebra Implementation Discussion

The group discussed implementing a "grind-ish version of algebra" where coefficients are treated as variables that can be normalized. Jay explained that the "denote" function evaluates polynomials and serves as a section of a surjection, allowing conversion between grind expressions and actual polynomial elements. Damiano noted that while a definitional approach to Grobner bases exists in Mathlib, implementing an algorithmic approach would only be worthwhile if it could help bypass complex computations through theoretical proofs.

### Kernel Function Performance Discussion

The team discussed performance considerations for a kernel-level function and debated different approaches to polynomial equality verification. Matthew explained that the code builds successfully but cannot currently prove that multiplying sorted polynomials results in a sorted polynomial. The discussion included a technical explanation about the "omit" feature in Lean, which allows controlling which instances are recorded by the kernel when elaborating statements. Damiano noted that while an ideal system would automatically track only used instances, practical implementations require heuristic adjustments. The conversation concluded with a brief mention of ongoing work using Claude to formalize Bridgeland's Annals paper on stability conditions.

### Code Generation Tool Optimization Issues

Matthew explained that the code generation tool he's working with has issues with local optimization, ignoring warnings, and making inappropriate substitutions in semantic contexts. He noted that while the tool works well when given specific tests to satisfy, it struggles with global optimization and can generate incorrect code when left to its own devices. Jay mentioned that the tool is having difficulty proving the monotonicity property of Grevlex under multiplication, which Michael clarified as a basic property of monomial orderings related to multiplication.

### Monomial Orders and Properties Discussion

The group discussed challenges with monomial orders and their properties, particularly regarding multiplication and zero rings. Jay explained that monomials form an abelian group and clarified that the underlying monomial is never zero. Michael mentioned potential issues with exterior algebra and noted how Macaulay 2 handles these situations by using a workaround. The conversation also touched on a benchmark problem, where Michael shared his approach of redefining sub-expressions to create smaller polynomial constraints, though he noted the process was still in progress.

### Macaulay 2 Certificate Implementation Discussion

Michael and Anton discussed the implementation of a certificate from Macaulay 2, focusing on handling sub-expressions and polynomial rings. Anton explained the computational challenges and potential optimizations, while Michael suggested focusing on sub-expressions that appear more than once. They also discussed the location of the code in a new "benchmark" directory within the "ideal membership" branch. The conversation was cut short as both participants had to leave for other commitments.

Michael mentioned he would be traveling to Paris the week after next and was unsure about bringing a computer. Jay updated the group about submitting an abstract to the ICMS conference in Waterloo, and suggested Michael could potentially discuss their work in his invited talk there.
