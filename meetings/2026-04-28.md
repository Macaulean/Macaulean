## Summary

The meeting focused on discussing polynomial representation and certification strategies for Macaulay 2 and Lean integration. The main discussion centered around finding optimal ways to represent polynomials as certificates for Lean to verify ideal membership, with participants exploring various approaches including Waring decomposition, sub-algebra representations, and straight-line programs. Jay presented recent refactoring work on polynomial representation code, including changes to the monomial type as a list and the expression type, though theorem proving is still pending. The group discussed serialization needs for these new representations, particularly implementing Merdi serialization for polynomial expressions with various coefficient types. They also touched on challenges with AI assistant usage, particularly regarding Claude and Codex token limits and performance differences between models. The conversation ended with agreement to continue these discussions in the following week.

## Topics

### Polynomial Certificate Optimization Discussion

The team discussed optimizing polynomial certificates for ideal membership to minimize the computational workload for Lean. Matthew explained the goal is to find a simpler representation of polynomials that would reduce the number of steps Lean needs to check during verification. Douglas suggested using Waring decomposition to express polynomials as sums of powers, though this approach may not generalize well. The group explored the idea of finding smaller subalgebras containing the polynomials, with Damiano comparing it to finding the optimal level of detail when explaining mathematical operations to another person. The discussion highlighted the challenge of balancing computational efficiency with the need to verify the original polynomial forms.

### Polynomial Expression Simplification Techniques

Damiano and Anton discussed computational heuristics for simplifying polynomial expressions, with Damiano sharing insights about how human mathematicians often intuitively know which parts of expressions are meaningful without full expansion. Anton proposed exploring certification of numerical approximations using straight-line programs (SLPs) and interval arithmetic, particularly for polynomial systems. Matthew provided context about ongoing work in Lean's computer algebra development, noting that while interval arithmetic is on the roadmap, it may take another 6 months for official implementation.

### Dopolynomial Code Refactoring Update

Jay reported refactoring the dopolynomial representation code, making it cleaner with monomials now represented as lists, though the serialization code still needs to be written. Jay mentioned that while some theorems need to be proven, particularly involving induction, the main structure is now separated from the theorems for better organization. Jay requested that Claude help with creating a serialization file to test the new representation's usefulness, as proving all the theorems would require significant effort.

### Cloud Computing Cost Challenges

Matthew discussed his experience with high cloud computing costs while working on Riemann surfaces, explaining that his current $200 subscription was nearly depleted due to running multiple Claude agents simultaneously for proof planning and implementation. He described the token limits in Claude, including 4-hour and weekly windows, which cause delays when limits are reached. Michael and Jay compared different AI models' performance and pricing, with Michael noting that ChatGPT was typically faster than Claude Code despite being less expensive.

### AI Model Performance and Development

The team discussed the performance of current AI models, with Matthew sharing his experience using multiple models for paper review and editing. Jay proposed focusing on developing code that can serialize expression types, allowing for seamless transfer of polynomial expressions and coefficients between systems. The goal is to create a robust system that requires minimal manual intervention, though they acknowledged that theorem proving remains more complex than simple data transfer.

### Polynomial Expression Computation Challenges

Michael and Damiano discussed challenges with finding simpler ways to write and modify polynomial expressions, particularly regarding Groebner bases and their relationship to original polynomials. They noted that while computers can handle these complex computations, finding efficient algorithms remains difficult due to the intractable nature of the problem. The discussion ended with Matthew asking about serialization with polynomial coefficients and Murray's required form, but this part of the conversation was not completed in the provided transcript.

### Polynomial Serialization Implementation Discussion

The team discussed implementing serialization for polynomial expression types in their system. Jay explained that currently only rationals and integers have serialization support, which is implemented in the McCalleen codebase. The discussion focused on creating type class instances for serialization, particularly for polynomial types, with Jay indicating this should be technically straightforward since the data structure is a list of lists. The team agreed to implement serialization for polynomial expressions and potentially prove related lemmas, though Jay noted this task would be tedious despite being conceptually simple.

### Polynomial Object Structure Discussion

The team discussed the structure and implementation of polynomial objects, with Jay explaining that polynomial Rn is a fixed-size policy acting as a list of terms without experts. Jay mentioned potential debates about the exact structure, including a possible rewrite to use polynomial instead of polyterm as the base. The group also discussed proving the length of powers in Structure Mon, with Jay noting that while proving it for specific monomials is straightforward, proving it abstractly presents challenges. The conversation ended with the team agreeing to meet next week, as several members had scheduling conflicts including Anton's faculty meeting.
